# IM Skill

当用户的问题涉及 IM 会话、商家消息、邀约、联系方式卡片、未回复场景、草拟回复、发送消息，或基于 IM 内容继续做选品和样品操作时，必须使用本 Skill。前端的一键总结按钮也只是发送一条普通用户文本，仍然需要由模型按本 Skill 判断是否调用工具。

## 可用 IM 工具

- `im_chat_summary`：Graph tool。对当前用户全部 IM 会话执行 Graph 总结，输出结构化卡片 JSON。该工具内部已经完成会话拉取、LLM 总结、JSON 校验和修复。
- `third_list_im_conversations`：查询当前用户的 IM 会话 ID 列表。
- `third_get_im_conversation_messages`：读取某个 IM 会话内的全部消息。
- `third_send_im_message`：向某个 IM 会话发送文本消息。

当 IM 任务需要继续处理商品、选品或样品时，可以结合以下业务工具：

- `third_recommend_products`
- `third_check_free_sample`
- `third_add_selection_cart`
- `third_get_selection_cart`
- `third_apply_free_sample`
- `third_buy_sample`
- `third_get_fulfillment_status`

调用任何业务工具时，`user_id` 必须使用系统消息中的当前登录用户 ID。不要向用户索要或猜测 `user_id`。

## IM 消息模型

IM 消息可能包含以下字段：

- `sender`：消息发送方，可能是用户或商家。返回值可能是 `USER` / `MERCHANT`，也可能是生成代码中的数字枚举。
- `message_type`：消息类型，可能是文本、邀约卡或联系方式卡片。返回值可能是 `TEXT`、`INVITATION_CARD`、`CONTACT_CARD`，也可能是数字枚举。
- `content`：消息正文或卡片摘要。
- `send_time`：发送时间。
- `invitation_card`：商家邀约卡信息，可能包含 `intro` 和 `products`。
- `contact_card`：联系方式卡片，可能包含 `name`、`phone` 和 `wechat`。

如果工具返回数字枚举，按以下规则理解：

- `sender = 1` 表示用户，`sender = 2` 表示商家。
- `message_type = 1` 表示文本，`message_type = 2` 表示邀约卡，`message_type = 3` 表示联系方式卡片。

## 通用处理流程

1. 对任何 IM 相关任务，先加载本 Skill。
2. 判断用户的具体目标：查询会话、总结消息、草拟回复、发送消息、提取商品、提取联系方式、跟进商家，或结合选品和样品工具继续操作。
3. 如果用户要求“总结当前 IM 会话”“总结聊天”“看看有哪些商家要回复”“整理 IM 邀约/沟通情况”等全量会话总结，必须直接调用 `im_chat_summary` 这个 Graph tool。不要自行调用 `third_list_im_conversations`、`third_get_im_conversation_messages` 后再手工总结。
4. 从当前对话、历史上下文和用户请求中收集必要信息。
5. 如果任务指向某个具体会话，但缺少 `conversation_id`，先调用 `third_list_im_conversations` 查询会话列表。
6. 如果查询到多个候选会话且仍无法确定目标会话，需要追问用户选择哪个会话。
7. 对单个指定会话的查看、分析或草拟回复，先调用 `third_get_im_conversation_messages` 读取对应会话消息。
8. 对会产生副作用的动作，尤其是发送 IM 消息，必须确认目标会话和消息内容明确。若不明确，先向用户确认。
9. 总结工具结果时，应给出关键业务证据，例如最新商家/用户消息、邀约商品、佣金或样品信息、联系方式卡片字段，以及已经执行的动作。

## 常见 IM 任务

### 查询会话列表

当用户询问自己有哪些 IM 会话时：

1. 调用 `third_list_im_conversations`。
2. 返回查询到的会话 ID。
3. 不要编造商家名称。只有读取消息或工具返回了商家信息后，才能提及商家名称。

### 全量 IM 会话总结

当用户要求总结当前 IM 会话、整理所有商家沟通情况、查看哪些会话需要回复、汇总新邀约/高佣/申样答复时：

1. 必须调用 `im_chat_summary` 这个 Graph tool，包括用户点击一键总结按钮后发送的普通文本请求。
2. 不要自行编排 `third_list_im_conversations` 和 `third_get_im_conversation_messages` 来完成全量总结。
3. `im_chat_summary` 返回的结构化结果已经按前端卡片需要组织，包含：
   - 新邀约。
   - 已同意。
   - 已拒绝。
   - 需继续沟通。
4. 回复用户时基于 `im_chat_summary` 的返回结果，不要补充工具结果中没有的商家名、商品信息或承诺。

### 读取或分析单个会话

当用户提供 `conversation_id`，或要求查看、分析某个会话时：

1. 调用 `third_get_im_conversation_messages`。
2. 用业务语言总结以下内容：
   - 商家的合作意图。
   - 邀约卡中的商品 ID、商品名称和佣金。
   - 文本中提到的佣金、样品、排期、内容要求等信息。
   - 用户尚未回复的问题，或商家仍在等待用户反馈的点。
   - 联系方式卡片中的姓名、电话、微信等信息。
3. 如果没有查到消息，说明当前用户在该会话中没有可读取的消息，不要编造内容。

### 从 IM 中提取邀约和商品

当用户询问某个 IM 里有哪些商品、是否包含邀约，或要求基于 IM 中的商品继续操作时：

1. 先读取会话消息。
2. 优先使用 `invitation_card.products` 中的商品 ID；文本内容只能作为辅助判断依据。
3. 如果有多个商品，保持原始顺序，并尽量给出商品 ID、名称和佣金。
4. 如果用户随后要求加选品车、申请样品、买样或查询履约状态，应使用提取到的商品 ID 调用对应工具。

### 草拟 IM 回复

当用户要求草拟或建议 IM 回复时：

1. 除非用户已经在当前请求中提供了足够的消息上下文，否则先读取会话消息。
2. 站在用户视角，为商家草拟简洁、自然、业务化的回复。
3. 根据业务场景调整话术：
   - 对邀约感兴趣：表达兴趣，并按需要询问样品、佣金、内容要求或排期。
   - 佣金协商：明确提出目标佣金比例，并请商家确认是否可以支持。
   - 样品申请：询问是否支持免费申样，以及预计寄出时间。
   - 类目不匹配或拒绝合作：礼貌说明暂时不接，并保留后续相关商品合作空间。
   - 商家追问未回复：直接回应商家最近的问题，不要绕开核心诉求。
4. 除非用户明确要求“发送”，否则只提供草稿，不调用 `third_send_im_message`。

### 发送 IM 回复

当用户要求发送 IM 回复时：

1. 明确目标 `conversation_id`。
2. 明确要发送的 `content`。
3. 如果用户已经给出明确要发送的文本，直接调用 `third_send_im_message`。
4. 如果用户要求“帮我写并发送”，但内容意图不够明确，先草拟回复并请用户确认。
5. 发送成功后，告诉用户已发送的内容，并在工具返回时说明消息 ID 或发送时间。

### 多步骤 IM 工作流

用户可能在一句话中把 IM、选品和样品操作组合起来。此时需要先规划依赖顺序，再执行工具。

示例：

- “看看这个 IM 邀约里有哪些商品，能免费申样的帮我申请”：读取 IM 消息 -> 提取商品 ID -> 必要时逐个检查免费申样资格 -> 对目标商品申请免费样品 -> 汇总成功和失败原因。
- “把这个商家的商品加进选品车，然后回复他我感兴趣”：读取 IM 消息 -> 提取商品 ID -> 加入选品车 -> 只有在用户明确要求发送时，才发送简短回复。
- “帮我回复商家问一下能不能给 25% 专属佣金”：如果有目标会话，先读取消息 -> 根据上下文草拟或发送佣金协商话术，是否发送取决于用户是否明确授权。

对于多步骤任务，不要要求用户重复提供可通过 IM 工具查询到的信息。只有当会话 ID、目标商品范围或副作用操作内容仍然不明确时，才向用户追问。

## 错误处理

1. 如果工具调用异常，不能向用户暴露技术细节，例如 RPC、HTTP、MCP、超时、限流、接口名、服务名、trace 或日志。只需告诉用户当前暂时无法完成查询或操作，请稍后再试。
2. 如果工具返回业务失败，例如会话不存在、没有消息、商品不满足样品条件或操作未成功，需要用业务语言告诉用户失败原因。
3. 如果多步骤任务部分成功，需要区分已完成、失败和未执行的部分。
4. 如果失败是因为目标会话、商品或消息内容不明确，应追问用户补充必要信息。

## 安全边界

- 不要向用户未指定或未确认的会话发送消息。
- 当前只能发送文本消息，不支持发送卡片、图片、附件或其他非文本内容。
- 不要声称商家已经同意、发货、审核通过或给出承诺，除非 IM 消息或工具结果明确说明。
- 不要展示原始 JSON，除非用户明确要求。
- 工具失败时，不要声称任务已完成。
